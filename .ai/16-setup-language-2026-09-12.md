# Язык установщика Windows

Пользователь попросил, чтобы при выборе языка Windows переводились и экраны установки. Реализовано в `win-11-lite.ps1`; каталог официальных загрузок — `data/winpe-26100.json`, происхождение и хэши описаны в `data/README.md`.

## Поведение

- `-SetupLanguage auto` включён по умолчанию. Установщик получает первый оставшийся после подготовки язык `AddLanguage`; без добавления языков остаётся исходный язык Windows.
- `-SetupLanguage original` сохраняет исходный язык установщика; дополнительных загрузок WinPE нет.
- `-SetupLanguage de-DE` выбирает язык установщика отдельно от языка установленной Windows.
- `-SetupLanguageSource <WinPE_OCs>` задаёт локальную папку CAB из ADK/LoF. Подходящий установленный WinPE add-on или WinPE_OCs на подключённом LoF также обнаруживается автоматически. Неподходящий автоматически найденный источник заменяется загрузкой правильного комплекта.
- Автозагрузка поддерживает **WinPE build 26100, amd64**. Для других билдов нужен соответствующий локальный источник. Версия берётся из индекса 2 исходного boot.wim, а не из предположения по install.wim.
- Подготовка производится до копирования ISO и обслуживания WIM. Ошибка загрузки/проверки/отсутствие обязательного LCU вызывает прежний RU/EN вопрос: продолжить без перевода установщика либо отменить сборку. Выбранный язык Windows при пропуске перевода установщика сохраняется.

## Файлы и обслуживание

Архив локализаций Microsoft имеет размер 320 140 822 байта (~305 МиБ). Это общий архив 37 языков; скрипт извлекает только выбранный язык. Для CJK/Thai отдельно подбираются обязательные WinPE font CAB из другого архива. Полный WinPE add-on на хост не устанавливается; 7-Zip и Windows Installer для работы нового кода не требуются, используется штатный expand.exe.

Хэши архивов проверяются по данным подписанного Microsoft bootstrapper. Затем проверяются CAB-идентичности LP/Setup/Setup-Client: язык, amd64, версия build. Готовые файлы получают SHA256-манифест кэша. Повторная подготовка может работать совсем без сети. При переносе проекта нужно переносить папку `data` вместе с PS1.

Важное уточнение, проверенное на исходном ISO пользователя: в boot.wim 26100.1742 **нет WinPE-LegacySetup-Package**. Этот optional component не равен запуску установщика с `/legacy`. Перевод обычного и классического установщиков доставляется обычными WinPE Setup CAB; языковой пакет LegacySetup добавляется только при наличии его нейтрального компонента, как и другие WinPE OC. Не превращать его в обязательную зависимость для -LegacySetup.

После LP устанавливаются локализации только присутствующих WinPE OC, затем подходящий LCU, затем задаётся язык WinPE. Для исходного LTSC оба boot-индекса имеют версию **10.0.26100.1742**. В этом случае используется уже подготовленный `LanguageUpdatePath` подходящего исходного билда либо скачивается KB5043080. Для неизвестной обновлённой ревизии можно указать `-SetupLanguageUpdatePath <MSU>` либо использовать совместимый подготовленный LCU из `-WithUpdates`.

Индекс 2 boot.wim обрабатывается до фиксации install.wim: `/Gen-LangINI` получает ещё смонтированный Windows-образ. Проверяются ключевые MUI-файлы, обслуженные ресурсы `sources/<язык>` копируются из boot.wim в дистрибутив, setup.exe/setuphost.exe синхронизируются между boot.wim и носителем. DISM задаёт SetupUILang, lang.ini копируется обратно в boot.wim. Финальный `/Get-Intl` должен подтвердить язык; ошибки интеграции не превращаются в успешный пропуск.

`TrimSources` сохраняет lang.ini, выбранный язык и каталог исходного языка. `SetupUILanguage` в answer-файле соответствует установщику, параметры языка Windows остаются отдельными. Проверка русских MUI установленной Windows продолжает сравнивать их с **исходным языком Windows**, а не с новым языком установщика. Информация о языке Setup и его LCU записывается в build-info.

## Проверки

- Скачан настоящий Microsoft WinPE archive; SHA1 совпал с подписанным манифестом. Исходный MSI также совпал с манифестом bootstrapper, чья Authenticode-подпись Valid/Microsoft Corporation.
- Настоящие русские CAB распакованы функцией сборщика; проверены update.mum, язык/архитектура/build. Повторное использование подготовленного комплекта прошло с заглушками, запрещающими сетевые обращения. Вывод 5.1 — `.ai/setup-language-validation/real-cabs-ps51.txt`; исследовательские файлы — `tmp/setup-language-research`.
- Из настоящего исходного ISO без монтирования Windows-образа прочитаны XML boot.wim, пакетные имена и состав sources/en-US. Подтверждены ревизия 1742 обоих индексов, наличие Setup/Setup-Client и отсутствие optional LegacySetup.
- По 368 проверок на PowerShell 7.6.6 и Windows PowerShell 5.1.19041.7725: Main 129, CMD 72, Guard 33, Downloads 80, SetupLanguage 54. Логи в `.ai/setup-language-validation`.
- Новый набор исполняет подготовку с отказами, реальную функцию интеграции с подменой DISM и настоящее урезание тестового дерева sources. Проверяет кэш, архитектуру/build/язык CAB, порядок LP/OC/LCU, наличие обязательных ресурсов, бинарную синхронизацию, lang.ini, выбор auto/original/явного языка, пропуск/отмену и отсутствие загрузок в DryRun.
- DryRun исходного ISO, индекс 2, ru-RU: язык установки ru-RU на обеих версиях PowerShell, в том числе с LegacySetup/TrimSources.
- В существующих тестах встречались ранее отмеченные непостоянные ошибки файлового ввода-вывода; один запуск guard 5.1 завершился ошибкой удаления занятого guard.lock, изолированный повтор прошёл. Код guard, Prepare/Finalize и Invoke-ProgressProcess сравнён с резервной копией и не менялся.

**Полная сборка ISO и загрузка новой версии в VM не выполнялись.** Подтверждены реальные входные пакеты и проверки с подменой обслуживания Windows, не результат установки.

Резервная копия перед изменением: `.ai/win-11-lite.before-setup-language-20260912.ps1`.
