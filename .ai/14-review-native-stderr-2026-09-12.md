# Ревизия сборщика 12.09.2026: ошибки и упрощения

Проверялась текущая `win-11-lite.ps1` (после правок ChatGPT). Синтаксис, тесты и DryRun проверены на PowerShell 7.6.6 и Windows PowerShell 5.1. Полная сборка ISO и установка в VM не выполнялись (нет административного токена).

## Подтверждённая ошибка: stderr нативных утилит под Windows PowerShell 5.1

В 5.1 при `$ErrorActionPreference = 'Stop'` любая нативная команда, которая пишет в stderr под перенаправлением (`*>&1`, `2>&1`, `*> $null`), бросает `RemoteException` на первой же строке. Код возврата до вызывающего не доходит. В pwsh 7 этого нет. Воспроизведено на этой машине:

```
reg.exe query HKLM\NoSuchKey *>&1 | Out-Null   -> THROWN (5.1), exit=1 (7)
takeown.exe /F C:\missing.txt /A *>&1          -> THROWN (5.1)
icacls.exe C:\missing.txt ... *>&1             -> THROWN (5.1)
dism.exe ... 2>&1                              -> не пишет в stderr, безопасно
```

Где это ломало сборку под 5.1 (двойной щелчок и «Выполнить с помощью PowerShell» запускают именно 5.1):

- Стадия 12, `reg.exe query` по службам: `SgrmBroker`/`SgrmAgent` в 24H2 отсутствуют, запрос пишет ошибку в stderr, сборка падала вместо `Start=4` для остальных служб.
- `Remove-Reg` (ключи Edge, которых в offline-кусте может не быть), удаление `OneDriveSetup` из Run, чистка записей шрифтов.
- `takeown`/`icacls` в `Remove-ImagePath`, заданиях телеметрии и CJK-шрифтах: ошибка на одном файле роняла весь прогон, а не пропускала файл.
- В гостевых `guard.ps1` и `Finalize.ps1` (всегда 5.1): ошибка `takeown` помечала проверку/финализацию как неудачную до вызова `Remove-Item`.

Исправление: `Invoke-NativeQuiet` (локальный `Continue`, возвращает код) и `Grant-ImagePathAccess` в сборщике; все `reg.exe` идут через уже защищённый `Invoke-RegCommand`; в guard добавлен `Grant-SystemAccess`, в Finalize — локальный скриптблок. Настройки вызывающего не меняются (проверено тестом).

## Прочие исправления

- `-Preset safe -RemoveWinRE -LegacySetup`: удаление WinRE молча пропускалось (проверка группы шла по пресету `balanced`), хотя план печатал «удалить», а копия рядом с ISO не сохранялась. Теперь ключ работает при любом пресете; блокирует только `-Keep WinRE`. Из строки «Не трогаем» убраны WinRE (есть отдельная строка плана) и Sandbox (правил нет).
- Недостижимые ветки после `Invoke-Dism` без `-AllowFail` (LP/Basic, LXP, Set-AllIntl, winget): функция сама бросает исключение, поэтому `else`-ветки с «мягкими» сообщениями никогда не выполнялись. Код приведён к фактическому поведению (отказ фатален), сообщения об этом оставлены в комментариях.
- `Finalize.ps1`: три `Add-Content` без `-Encoding UTF8` (в отличие от Prepare и guard) — русские сообщения могли портиться.
- Инициализация `$script:BootMounted`.

## Упрощения

- Дубли `Remove-Reg` для Edge заменены одним циклом по тем же ключам, что чистит Finalize.
- Чтение паспорта WIM вынесено в `Get-WimImageList` (использовалось дважды: диалог и стадия 3).
- Один проход по дереву ISO вместо двух (снятие read-only и подсчёт объёма).
- `Dismount-Hives`: `GC.Collect` один раз до цикла, ранний выход при пустом списке.
- Диалог: значение по умолчанию рабочей папки берётся из `$WorkDir`, а не дублируется.

## Реальная сборка 20260912-132101 под Windows PowerShell 5.1 и WebView2 после LCU

Пользователь запустил полную сборку из 5.1 (`-WithUpdates`, ru-RU, winget, Guard, RemoveWinRE, LegacySetup, TrimSources). Стадия 15 прошла: `reg query` по отсутствующим службам больше не роняет сборку (отключено 15 служб из 18). Сборка упала на стадии 17: `Удалён защищённый компонент WebView2: ...\Program Files (x86)\Microsoft\EdgeWebView`.

Разбор по DISM-логу (`log\..._20260912-132159.dism.log`) и 7-Zip-листингу образов:

- В исходном 26100.1742 встроенный WebView2 — CBS-компонент `amd64_microsoft-edge-webview_..._10.0.26100.1` (пакет `Microsoft-Edge-WebView-FOD-Package`). Его полный runtime лежит в `Windows\System32\Microsoft-Edge-WebView`, а `Program Files (x86)\Microsoft\EdgeWebView\Application\122.0.2365.106` — жёсткие ссылки на те же файлы.
- KB5124008 (26100.9445) приносит компонент `10.0.26100.9444` = WebView2 151.0.4129.59. В 13:43:25 CBS выполняет `Unproject package: Microsoft-Edge-WebView-FOD-Package~...~10.0.26100.1` (hard reserve −559 МБ), и каталог версии 122 из Program Files (x86) исчезает. Новый компонент проецируется в `System32\Microsoft-Edge-WebView` (там появляется `151.0.4129.59.manifest`). Ни один файловый шаг сборщика WebView2 не трогал: в стадии 14 нет записей об Edge, в IoT LTSC браузера Edge нет вовсе.
- Предыдущий удачный ISO (`out\old2`, 3 121 188 864 байта) собирался без KB5124008: WinSxS 7.69 → 7.93 → 7.55 ГБ. Поэтому раньше это не проявлялось.

Исправление: `Get-WebViewRuntimeRoots` ищет `msedgewebview2.exe` во всех трёх известных корнях; `Assert-ImageFileState` бросает исключение только если runtime не остался нигде. Если запомненный при монтировании корень опустел, выводится предупреждение с версией из манифеста и оставшимися корнями, а в `image-audit.json` пишется блок `WebView`. Добавлены 3 проверки в тесты (пропажа x86-копии при живом System32, запись в аудит, полная пропажа по-прежнему блокирует commit).

Не проверено и требует VM: регистрирует ли Windows WebView2 151 при первой загрузке (появление `Program Files (x86)\Microsoft\EdgeWebView\Application\151.0.4129.59` и ключа `EdgeUpdate\Clients\{F3017226-...}`), работают ли приложения с WebView2. До этого безопасный вариант — сборка без `-WithUpdates`, как подтверждённый ISO от 00:26.

Попутно: у одиночного `PSCustomObject` в 5.1 нет свойства `Count`, из-за чего «Встроенных приложений:» печаталось пустым; списки capabilities/packages/appx обёрнуты в `@()`.
