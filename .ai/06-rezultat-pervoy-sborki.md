## 3. Что не сработало — и уже исправлено

| Проблема | Причина | Исправление |
|---|---|---|
| **Удалено 0 пакетов из 66** | `dism /Get-Packages` показывает только FOD-пакеты, языковые и rollup'ы (~50 штук). Компоненты из `servicing\Packages` (Recall, CJK, WMP, IE) входят в Foundation и через `/Remove-Package` недоступны | Правила переписаны под реальные имена FOD; остальное убирается возможностями и файлами |
| **CJK-шрифты остались (254 МБ)** | Пытался удалить пакетом, которого не существует | Удаление файлами по маске + чистка записей в реестре шрифтов |
| **AI-компоненты не чистились** | Правила добавлены уже во время прогона | Группа `AI` в пресете `balanced` |
| `oscdimg` — `Could not open boot sector file ""path""` | PowerShell добавляет свои кавычки к закавыченному аргументу | Относительные пути + `Push-Location` |
| `reg add ...\Explorer\Advanced /v TaskbarDa` — код 1 | Повторился 11.09 на стадии 13; исходный текст ошибки утрачен | Запись заменена политикой отключения виджетов, диагностика сохранена; см. [аудит](08-audit-2026-09-11.md) |
| После аварийного завершения DISM остаются загруженные кусты `{GUID}path` | Держат файлы образа, мешают отцепить и удалить рабочий каталог | `Clear-OrphanHives` в preflight и в `finally` |

## 4. Сколько ещё можно выжать

При сохранении обслуживаемости образа:

| Что | Несжатых МБ | Примерно на ISO |
|---|---:|---:|
| CJK-шрифты (исправлено) | 254 | ~65 |
| AI-компоненты (AIFabric, AIX, AugLoop, Copilot.msix) | 12 | ~3 |
| FOD-пакеты (обои, TabletPCMath, Hello Face, SenseClient) | ~150 | ~40 |
| **Итого реалистично** | **~420** | **~110 МБ** |
| WebView2 — только если готовы к несовместимости с частью софта | 714 | ~180 |

**То есть даже после всех исправлений ISO будет ~4.5 ГБ, а без WebView2 — ~4.3 ГБ.**

Причина одна: WinSxS в обновлённом образе — 10.9 ГБ, и это не мусор, а хранилище компонентов, необходимое для обслуживания. Убрать его = потерять возможность обновляться и доставлять компоненты (ровно то, что сделали в Full.Fast: там WinSxS 50 МБ вместо 10 900).

## 5. Три пути дальше — нужно решение

### Вариант A. Оставить как есть
- ISO **~4.5 ГБ** после исправлений
- Система из коробки на 26100.9445, все патчи по сентябрь 2026
- Полностью обслуживаемая: Windows Update работает, компоненты и языки доставляются
- Установка сразу актуальная, интернет после установки не нужен

### Вариант B. Не встраивать обновления (`-UpdateMode none`)
- ISO **~3.0–3.2 ГБ** (WinSxS остаётся 7.4 ГБ, плюс наши удаления)
- Система ставится как 26100.1742, обновления приезжают через Windows Update при первом подключении (30–60 минут и пара перезагрузок)
- Обслуживаемость полная
- Сборка быстрее: не нужно качать 4.9 ГБ и тратить 16 минут на интеграцию
- **Логика:** зачем встраивать 4.4 ГБ обновлений в ISO, если Windows Update скачает их сам? Смысл есть только если ставите на машины без интернета или разворачиваете часто

### Вариант C. Вырезать WinSxS (как Full.Fast)
- ISO **~2 ГБ**
- Образ **необслуживаемый**: нельзя доставить .NET 3.5, языки, компоненты; будущие обновления могут не встать
- Именно этим путём идут сборщики, и именно поэтому их образы «тупиковые»

**Моя рекомендация — вариант B** как основной режим, с возможностью собрать по варианту A, когда нужен полностью автономный образ. Оба уже поддерживаются одним ключом `-UpdateMode`.
