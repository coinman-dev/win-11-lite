# Рабочая память win-11-lite

Обновлено 12.09.2026. Этот файл предназначен для продолжения работы в новой сессии, в том числе в WSL2. Историю чата переносить не требуется: ниже сохранены существенные решения, ошибки и результаты.

## Задача и ограничения пользователя

- Аудит и исправление PowerShell-сборщика облегчённых Windows 11 ISO: Edge, русский интерфейс, пропуск обновлений OOBE, размер образа, совместимость.
- Сборщик двуязычный: `-UILang ru|en`. Язык сборщика и язык Windows — разные параметры.
- `max` не смягчать: это сознательный максимум с предупреждением о потере совместимости.
- `balanced` удаляет необязательное, но сохраняет WebView2, обслуживание Windows, Hyper-V/WSL и необходимые драйверы/языковые компоненты.
- ResetBase выключен по умолчанию. Он делает уже установленные обновления неудаляемыми; универсальная поломка будущих LCU на любом 26100+ не подтверждена источниками. Не удалять checkpoint-пакеты ради красивого счётчика очистки.
- Сейчас пользователь попросил временный видимый debug guard при каждом входе. Он включён по умолчанию при `-Guard`; позже отключается `-GuardDebug:$false`.

## Рабочие пути и важная причина прежних ложных результатов

- Актуальный Windows-проект: `D:\Development\win-11-lite`.
- GitHub: приватный репозиторий `coinman-dev/win-11-lite`, ветка `main`. Windows `gh` находится в `C:\Program Files\GitHub CLI\gh.exe`; Git и gh также доступны в Ubuntu WSL. В Windows-папке пока нет `.git`. Для публикации актуальных Windows-файлов создана отдельная копия `/home/modulator/Development/.win-11-lite-publish-1789224711744`; прежняя WSL-копия с незакоммиченными изменениями сохранена. Не пушить старый WSL-скрипт поверх текущей Windows-версии. При синхронизации переносить PS1, data, tests и документацию; сборочные файлы и локальные снимки исключены через `.gitignore`.
- Ранее проект был в `E:\win-11-lite`. Hyper-V продолжал монтировать старый ISO из `E:\win-11-lite\out`, пока новые ISO создавались на D:. Имена совпадали. Из-за этого пользователь долго не видел исправлений и сообщал о вернувшемся Edge/английских Параметрах/обновлениях OOBE.
- Пользователь обнаружил ошибку пути и удалил старый ISO. Правильная сборка заработала; на скриншоте Параметры русские. Не возобновляй старые гипотезы о сломанной финализации на основании тех скриншотов.
- В новых сборках есть `win11-lite-build.json` в корне ISO и `C:\Windows\Setup\Scripts\Win11Lite\build-info.json` в гостевой ОС. Там ID, дата, исходный/выходной пути и режимы.
- WSL: Ubuntu, пользователь `modulator`, проект `/home/modulator/Development/win-11-lite`, доступ из Windows через `\\wsl.localhost\Ubuntu\home\modulator\Development\win-11-lite`.
- В WSL на момент переноса были только старые PS1 и старый план. Актуальный снимок скрипта/тестов скопирован в `.ai/windows-reference`; текущие Windows-отчёты — в `.ai/windows-history`. Старые файлы WSL не перезаписывались.
- Код сборщика и тесты ориентированы на Windows. В WSL не были доступны pwsh/powershell.exe; диски Windows ранее не монтировались в `/mnt/c`. Для переноса файлов использовался UNC, а не предположение о `/mnt/c`.
- Авторизация Codex ранее была отдельно скопирована в `/home/modulator/.codex/auth.json` с правами 600. Секретов авторизации в памяти проекта нет.

## Существенные исправления, которые нужно сохранить

1. `Language.Basic` не устанавливался из-за имени FoD CAB: DISM искал полную CBS-идентичность с `~31bf3856ad364e35~amd64~~.cab`. Создаётся правильное имя в рабочем каталоге. LP и Basic обязательны; ошибки не замалчиваются.
2. Русский LP из UUP может быть 26100.1 даже при названии набора 26100.1742. После языка повторно применяется исходный LCU (для 26100.1742 — KB5043080) либо выбранный новый LCU. Проверяются MUI и PRI Параметров.
3. SetupUILanguage задаёт язык установщика, UILanguage — Windows. Теперь `-SetupLanguage auto` по умолчанию переводит установщик на первый добавляемый язык Windows, готовя пакеты WinPE до сборки. `-SetupLanguage original` сохраняет исходный язык (прежнее поведение); можно задать отдельный язык. Обе раскладки RU/EN остаются в answer-файле. Для проверки MUI Windows отдельно сохраняется исходный язык, независимо от Setup. Отдельный FirstLogon.ps1 с принудительной сменой языка и дублирующий RunOnce удалены после уточнения про старый ISO.
4. После скриншотов повторных обновлений OOBE подготовка усилена: повторное обнаружение адаптеров, повторная проверка из SetupComplete, временное исходящее правило Win11Lite-OOBE-Temporary-Outbound-Block для поздних интерфейсов. Finalize ждёт Kernel32 OOBEComplete даже при FirstLogon; ранний вызов запускает скрытое ожидание, не удерживая открытие рабочего стола. Маркер oobe-complete предотвращает позднюю повторную блокировку. Сохранённые адаптеры, собственное правило и временные политики восстанавливаются независимо от отказа Edge. Новое поведение в VM пока не проверено; точная причина регрессии требует гостевых prepare.log/finalize.log. См. `17-oobe-and-firefox-2026-09-12.md`.
5. Edge очищается offline и после OOBE; WebView2 сохраняется в balanced. Финализатор защищён от одновременного запуска и освобождает блокировку до возврата ненулевого кода.
6. TaskbarDa давал ошибку записи. Используется политика `Policies\Microsoft\Dsh\AllowNewsAndInterests=0`. reg.exe сохраняет исходный текст ошибки.
7. Конечный файл Copilot MSIX в смонтированном WIM имел reparse-атрибут. Исправлена проверка пути; переходы через ссылки в родительских каталогах запрещены.
8. `0x800F0825` у Sense сопровождается `Permanent package cannot be uninstalled`. В balanced после отказа capability пропускаются повторные удаления его базового и языковых пакетов. Метаданные CBS не считаются удалёнными.
9. Одна операция DISM может несколько раз показать 0–100%. Если процесс ещё работает, промежуточные 100% теперь заменяются на `...`, движущуюся полосу и «ожидание завершения»; таймер обновляется даже после закрытия stdout/stderr. `100% — готово` — только после успешного выхода, отказ — ERR. Индикация помечает этапы, помещается в ширину консоли, не заполняет transcript каждым кадром. `Invoke-ProgressProcess` (прежний `Invoke-DismProgress`) возвращает `ExitCode`/`Output`: DISM печатает проценты в stdout, oscdimg — в stderr (`-ProgressOnStdErr`), robocopy `/NP` получает процент из `-GetPercent` → `Get-CopyPercent` (опрос не чаще 2 с, максимум 99 % до выхода). Полоса есть у языков/компонентов/LXP, анализа WinSxS, удаления Recall, драйверов, boot.wim, копирования и записи ISO. Ошибка oscdimg показывает хвост вывода. `-WorkingDirectory` обязателен вместо `Push-Location`. См. `19-progress-completion-2026-09-12.md`.
10. Install-Firefox.cmd ломался из-за UTF-8 + LF: CMD выдавал обрывки команд, `os`, `lang`. Все CMD записываются через Write-WindowsBatchFile: UTF-8 без BOM, CRLF. Теперь одноразовый Install-Firefox.cmd удаляет себя только после успешной установки; ошибка/отмена сохраняют его, Firefox.lnk не удаляется. Write-FirefoxInstallerFile даёт Users право Delete только на этот файл, без права изменения. Самоудаление проверено настоящим cmd.exe, включая пути с кириллицей/пробелами/&/!.
11. Установочные вызовы Prepare/Finalize скрыты и NonInteractive. Перенаправление SetupComplete идёт в setupcomplete.log, а Prepare пишет свой prepare.log — нет двух писателей одного файла.
12. Безопасная уборка обрабатывает собственные mount/hives, сохраняет рабочие файлы при ошибке unmount, защищает источники и выходной ISO. `-Keep` приоритетнее `-RemoveExtra`. Код DISM 3010 допускается как успех с необходимостью перезагрузки.
13. Windows PowerShell 5.1 при `Stop` превращает stderr нативной команды под перенаправлением в исключение (pwsh 7 — нет). Все `reg.exe` идут через `Invoke-RegCommand`, `takeown`/`icacls` — через `Invoke-NativeQuiet`/`Grant-ImagePathAccess`; в guard и Finalize — локальный `Continue`. Не возвращать прямые вызовы с `*>&1`. `-RemoveWinRE` работает при любом пресете, блокирует только `-Keep WinRE`.
14. WebView2 после LCU: KB5124008 заменяет встроенный компонент (122.0.2365.106 → 151.0.4129.59), CBS сам убирает каталог версии из `Program Files (x86)\Microsoft\EdgeWebView`, runtime остаётся в `Windows\System32\Microsoft-Edge-WebView`. Это не удаление; проверка требует наличия runtime хотя бы в одном известном корне и предупреждает о переносе. Регистрацию WebView2 при первой загрузке обновлённого образа в VM ещё не проверяли. Единственная подтверждённая установка была без KB5124008.
15. После отказа DNS GitHub на стадии 16 все загрузки перенесены до копирования ISO, очистки WorkDir, экспорта и монтирования WIM. Подготавливаются LCU + checkpoints, .NET, Pack/Basic, language-repair LCU и весь winget. При отказе пользователь выбирает пропуск компонента или отмену (по умолчанию); без интерактивного ввода — отмена. Независимые компоненты сохраняются; без обязательного repair LCU пропускается добавление языков целиком. Полные комплекты проверяются по манифестам SHA256; частичные файлы `.part` не считаются готовыми. Языки/winget/repair используют готовый кэш без API; WithUpdates пробует последние обновления, при ошибке возвращается к полному проверенному кэшу. После подготовки сетевых вызовов нет. Отмена сохраняет прошлый WorkDir. Подробности — `15-offline-downloads-2026-09-12.md`.
16. Локализация boot.wim: `data/winpe-26100.json` содержит проверенную карту официального WinPE add-on (37 языков x64; первый архив ~305 МиБ). Сохранять папку data рядом с PS1. Только скачивание/распаковка, add-on на хост не ставится. Источник других билдов — `-SetupLanguageSource <WinPE_OCs>`. Исходный boot.wim имеет build 26100.1742, поэтому после LP/OC повторяется соответствующий LCU; при необходимости есть `-SetupLanguageUpdatePath`. В исходном boot.wim нет optional WinPE-LegacySetup: это не обязательная зависимость `/legacy`. Локализуются только имеющиеся OC. Индекс 2 обрабатывается до фиксации install.wim для Gen-LangINI; Setup binaries синхронизируются с носителем, TrimSources сохраняет lang.ini и выбранный/исходный языки. При отказе подготовки можно оставить исходный язык Setup, сохранив язык Windows. Реальные русские CAB проверены, установка новой версии в VM ещё не проверена. Подробности — `16-setup-language-2026-09-12.md`.
17. По просьбе пользователя логирование не должно засорять консоль строками ПОДРОБНО/VERBOSE. Debug/LogFile/мастер подавляют verbose/debug-потоки; команды DISM и технические сообщения пишутся через Write-DiagnosticLog в отдельный .details.log. Transcript — основной .log; DISM — .dism.log уровня 4 (также при LogFile без Debug). Не возвращать VerbosePreference=Continue для включения логов. См. `18-quiet-logging-2026-09-12.md`.

## Guard — текущее устройство

- В образ при `-Guard` записываются `Windows\Setup\Scripts\Win11Lite\guard.ps1` и `guard.json`.
- `Prepare.ps1` регистрирует задачу `win-11-lite guard`: SYSTEM, любой вход, задержка 30 секунд, запрет одновременных экземпляров.
- Сам SYSTEM работает в неинтерактивной сессии; WindowStyle Normal не делает его окно видимым. Поэтому отдельная задача `win-11-lite guard debug` запускает наблюдатель от вошедшего пользователя (группа Users, Limited). После проверки, что OOBE завершён, он открывает видимый PowerShell с живым guard.log.
- Debug-окно показывает последние 60 записей и новые строки. Закрытие окна не останавливает worker. Во время OOBE/defaultuser0 оно не открывается.
- Отключить окно в новой сборке: `-Guard -GuardDebug:$false`. В уже установленной тестовой ОС: `Disable-ScheduledTask -TaskName 'win-11-lite guard debug'`. Сам guard остаётся включённым. `-Debug` сборщика — отдельный параметр.
- Guard проверяет Edge, выбранные машинные политики/службы, возможности, установленные и provisioned Appx, выбранные файлы и каталоги. Шаблоны берутся из правил сборки и учитывают Keep/защищённые компоненты. NGEN не вычищается на каждом входе; Sense не пытаются постоянно удалить как Permanent capability.
- Логи каждого запуска содержат START/CHECK/OK/CHANGED/PENDING/SKIP/ERROR/END. Ошибки не считаются успехом, результат операции перепроверяется; отказ одной инвентаризации не блокирует независимые проверки. Ошибки дают ненулевой результат задачи.
- Отдельный FirstLogonCommands вызывает Finalize.ps1 напрямую. Финализатор удаляет только собственную однократную задачу, не guard. Существование ещё не удалённой finalize-задачи само по себе больше не отключает guard.
