# win-11-lite

[![Windows 11 x64](https://img.shields.io/badge/Windows%2011-x64-0078D4.svg)](#требования-и-поддерживаемые-образы)
[![PowerShell](https://img.shields.io/badge/PowerShell-5.1%20%7C%207-5391FE.svg)](#требования-и-поддерживаемые-образы)
[![Tests](https://img.shields.io/badge/tests-1304-success.svg)](#состояние-проверок)

**win-11-lite** собирает уменьшенный и ориентированный на конфиденциальность установочный ISO Windows 11 из оригинального x64-образа Microsoft. Он удаляет выбранные встроенные приложения и компоненты, применяет настройки конфиденциальности и OOBE, умеет интегрировать обновления, языки и драйверы, затем экспортирует одну выбранную редакцию Windows в новый загрузочный ISO.

Сборщик состоит из одного файла PowerShell. Достаточно скачать [`win-11-lite.ps1`](win-11-lite.ps1); каталоги `data` и `tools`, генератор, собственный EXE, Git и GitHub CLI для работы не нужны.

> [!WARNING]
> Проект намеренно удаляет компоненты Windows. Стандартный пресет `balanced` удаляет Microsoft Defender, «Безопасность Windows», Recall и другие AI-компоненты, речь/OCR, Media Player, Xbox/Game Bar и выбранные потребительские приложения. Сначала просмотрите план через `-DryRun` и проверьте готовый ISO в VM.

## Быстрый запуск

Скачайте единственный нужный файл:

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/coinman-dev/win-11-lite/main/win-11-lite.ps1 -OutFile .\win-11-lite.ps1
.\win-11-lite.ps1
```

Запуск без параметров открывает мастер. Он находит ISO рядом, спрашивает редакцию и пресет и запрашивает права администратора перед сборкой.

Если выбранный ISO занят другим процессом, недоступен или не содержит читаемого образа Windows, мастер сразу останавливается с путём ISO и причиной ошибки. Вопрос о рабочей папке и остальные шаги не выполняются.

Прочитать образ и показать полный план без прав администратора и изменений:

```powershell
.\win-11-lite.ps1 -InputIso .\iso\original.iso -Index 2 -DryRun
```

Компактная сборка Pro с Guard:

```powershell
.\win-11-lite.ps1 -InputIso .\iso\original.iso -Edition Professional -Preset balanced -Guard Standard -LegacySetup -TrimSources -RemoveWinRE -SaveWinRE
```

Добавить текущие обновления, winget, драйверы и русский язык Windows/установщика:

```powershell
.\win-11-lite.ps1 -InputIso .\iso\original.iso -Index 2 -WithUpdates -WithWinget -DriversDir .\drivers -DownloadLanguage ru-RU -Guard Standard -Debug
```

По умолчанию результат записывается в `out\<имя-исходника>_lite.iso`. `-UILang ru` и `-UILang en` выбирают язык сообщений сборщика независимо от языка Windows в образе.

## Зачем нужен Guard

Удаление компонента из offline-образа не всегда остаётся постоянным. Накопительное или функциональное обновление может снова подготовить встроенное приложение, вернуть файлы Edge или Defender, включить службу либо сбросить политику. **Guard поддерживает выбранное состояние сборки после установки Windows.**

Задача `win-11-lite guard` запускается от `SYSTEM` через 30 секунд после входа пользователя. Она ждёт системного подтверждения завершения OOBE, затем:

- читает список приложений, provisioned-пакетов, возможностей Windows, файлов и каталогов, выбранных сборкой;
- повторно удаляет вернувшиеся цели и при необходимости снова очищает Edge;
- проверяет и восстанавливает выбранные машинные политики;
- отключает или останавливает восстановленные службы;
- перепроверяет результат каждой операции и не считает попытку успешным удалением;
- хранит историю, чтобы отличать первую проверку от подтверждённого повторного появления.

Guard не является антивирусом, резервным копированием или универсальным ремонтом Windows. Он поддерживает конкретные удаления и настройки, записанные при сборке ISO.

### Режимы Guard

У `-Guard` четыре значения:

| Режим | Поведение |
| --- | --- |
| `None` | Не встраивать Guard. Значение по умолчанию в командной строке. |
| `Standard` | Фоновая проверка и короткий итог после завершения. Значение по умолчанию в мастере. |
| `Debug` | Живое окно подробного журнала и полный итог. |
| `Silent` | Проверка без пользовательского окна; все отчёты сохраняются на диск. |

```powershell
-Guard None
-Guard Standard
-Guard Debug
-Guard Silent
```

Старых отдельных параметров `-GuardMode` и `-GuardDebug` больше нет.

### Отчёты Guard

Отчёты хранятся в `C:\Windows\Setup\Scripts\Win11Lite\`:

| Файл | Содержимое |
| --- | --- |
| `guard-summary.txt` | Короткие счётчики, имена найденных объектов, результаты, ошибки и команды управления Guard. |
| `guard-report.txt` | Полный читаемый отчёт с состоянием до/после и техническими подробностями. |
| `guard-report.json` | Структурированный отчёт с ID запуска, полнотой инвентаризации и результатом каждого объекта. |
| `guard-state.json` | История для определения повторного появления и повторного исправления. |
| `Logs\YYYY-MM-DD.log` | Общий ежедневный журнал Guard, подготовки, финализации и обоих запускателей: полные отчёты Guard, вывод и коды завершения рабочих процессов. |

Журналы хранятся **за сегодня и предыдущие 29 дней**. Повторные запуски дописываются в тот же файл; после полуночи создаётся новый. Старые ежедневные файлы удаляются автоматически при первой записи гостевого сценария за день. Debug продолжает читать свою проверку Guard при переходе через полночь. Последние `guard-report.txt/json` и `guard-summary.txt` перезаписываются после каждой проверки; `guard-state.json` остаётся рабочим состоянием для определения вернувшихся компонентов. Файлы журналов прежнего формата больше не растут и удаляются, когда дата последней записи выходит за срок хранения. Очистка затрагивает только известные файлы журналов и не проходит через ссылки файловой системы.

Standard и Debug перед закрытием показывают путь к полному отчёту. Неизвестное состояние инвентаризации, незавершённое обслуживание и ошибка проверки не считаются успешным удалением.

Отключить будущие запуски Guard в Терминале от администратора:

```powershell
schtasks.exe /Change /TN "\win-11-lite guard" /Disable
```

Включить обратно:

```powershell
schtasks.exe /Change /TN "\win-11-lite guard" /Enable
```

Отключение задачи не останавливает уже начатую проверку и не возвращает удалённые приложения или политики. После включения Guard запустится при следующем входе. Обновление самого Guard требует пересборки ISO.

> [!IMPORTANT]
> Антивирус может заблокировать Guard как угрозу. Guard скрыто работает от `SYSTEM` и отключает службы и политики защиты Windows, а поведенческий анализ принимает это за вредоносную программу, отключающую защиту (например, Avast сообщает `IDP.HEUR`). Не помещайте файл в карантин: тот же `Win11Lite.ps1` выполняет и подготовку, и финализацию. Вместо этого добавьте `C:\Windows\Setup\Scripts\Win11Lite\Win11Lite.ps1` в исключения антивируса. Изменять его могут только `SYSTEM`, Администраторы и TrustedInstaller. Сборщик повторяет это предупреждение в плане сборки и в итоговом отчёте, если Guard включён.

Если окно отчёта открывается и закрывается за секунду, а файлы отчётов при этом пишутся, проверьте `%TEMP%` у вошедшего пользователя. Некоторые сторонние установщики перезаписывают `HKCU\Environment` и теряют его значения `TEMP` и `TMP`; сеанс наследует `C:\Windows\TEMP`, куда обычному пользователю разрешена запись, но не перечисление каталога, поэтому проверка окончания OOBE не может собрать вспомогательный код и окно закрывается без вывода. Причина теперь записывается в дневной журнал. Вернуть стандартные значения Windows можно без прав администратора:

```powershell
reg.exe add "HKCU\Environment" /v TEMP /t REG_EXPAND_SZ /d "%USERPROFILE%\AppData\Local\Temp" /f
reg.exe add "HKCU\Environment" /v TMP  /t REG_EXPAND_SZ /d "%USERPROFILE%\AppData\Local\Temp" /f
```

## Почему удаляется Recall

Windows Recall — необязательная функция Copilot+ PC. После согласия пользователя Windows сохраняет скриншоты активного экрана каждые несколько секунд и при изменении активного содержимого, затем индексирует изображения и распознанный текст для поиска. Microsoft сообщает, что снимки хранятся локально в зашифрованном виде, доступны после Windows Hello и самим Recall не отправляются в Microsoft. Фильтрация чувствительных данных включена по умолчанию. [Описание Recall](https://support.microsoft.com/en-us/windows/ai/ai-features/retrace-your-steps-with-recall), [архитектура конфиденциальности](https://support.microsoft.com/en-us/windows/privacy/privacy-and-control-over-your-recall-experience).

Эта защита не делает историю экрана безразличной. Всё, что показано в терминале, браузере, почте, базе данных, облачной панели, окне пароля или документе клиента, потенциально может попасть в сохранённый снимок. Microsoft отмечает, что части отфильтрованных сайтов всё равно могут попасть в снимок, а удалённые клиенты захватываются, если не реализовали защиту экрана. В корпоративном руководстве разрешение скриншотов содержимого, которое нельзя допустить к утечке, прямо названо общим риском безопасности. [Управление Recall](https://learn.microsoft.com/en-us/windows/client-management/manage-recall#bring-your-own-device-byod-considerations).

Это особенно важно на личном компьютере, с которого администрируют серверы. SSH-терминалы, хостинг-панели, API-токены, внутренние имена узлов, записи клиентов и личные сообщения появляются на экране в обычной работе. Recall сам не отправляет эти данные в облако, но создаёт дополнительное поисковое хранилище истории экрана. Скомпрометированный сеанс Windows, небезопасный экспорт или удалённый клиент без защиты захвата превращают эту историю в дополнительный источник возможной утечки.

Поэтому `balanced` и `max` применяют удаление и блокировку:

- задают `AllowRecallEnablement=0` и `DisableAIDataAnalysis=1` для компьютера и профиля по умолчанию;
- запрещают провайдеры и экспорт Recall, отключают Click to Do и агент Параметров;
- в `balanced` запрашивают штатное удаление optional feature `Recall` вместе с payload;
- удаляют найденные файлы/пакеты Recall, Copilot, AI Fabric, AIX и AugLoop;
- передают основные политики Recall/Copilot и выбранные AI-пути в Guard, чтобы обновление не вернуло их незаметно.

Microsoft документирует, что отключение политики Allow Recall переводит компонент в отключённое состояние, удаляет его файлы и после перезагрузки удаляет сохранённые снимки. Для удаления payload также указана команда `Disable-WindowsOptionalFeature -Online -FeatureName "Recall" -Remove`. [Политики Recall](https://learn.microsoft.com/en-us/windows/client-management/manage-recall#allow-recall-and-snapshots-policies).

В текущей потребительской Windows Recall требует согласия пользователя, а на управляемых коммерческих устройствах по умолчанию удалён. Проект убирает его потому, что его цель — облегчённая система без сохраняемой временной шкалы экрана, а не потому, что Recall тайно отправляет каждый снимок.

## Пресеты

Пресеты накопительные: `balanced` включает `safe`, а `max` включает оба и добавляет более разрушительные правила.

| Пресет | Для чего | Основные действия |
| --- | --- | --- |
| `safe` | Небольшая очистка конфиденциальности с сохранением Defender и обычных приложений | Удаляет браузер Edge и ярлыки, сохраняя WebView2; отключает службы/политики телеметрии, рекламу, рекомендации и виджеты; применяет настройки установки/OOBE. |
| `balanced` | Стандартный облегчённый рабочий стол | Добавляет удаление Defender/«Безопасности Windows», речи/рукописи/OCR/синтеза, Recall/Copilot/AI, классического и современного Media Player, заглушки IE, классического Paint, Steps Recorder, диагностики, CJK-шрифтов/IME там, где это допустимо, установщиков OneDrive, кэша NGEN, Xbox/Game Bar, Family, To Do и потребительских приложений. Сохраняет Store/MSIX, App Installer/winget, WebView2, обслуживание, Hyper-V и WSL. |
| `max` | Намеренно агрессивное уменьшение | Дополнительно удаляет WebView2/Edge Update, резервные копии компонентов, PowerShell ISE, WMIC, Hello Face, распознавание формул, факс/сканирование и дополнительные FoD. Совместимость приложений и будущее обслуживание могут сломаться. VBScript сохранён как явная зависимость скрытого запуска установки. |

Среди Appx-целей: Clipchamp, Bing News/Weather, Get Help/Get Started, Office Hub, Solitaire, Feedback Hub, Phone Link, новый Outlook, Teams, Xbox/Game Bar, Family и Microsoft To Do. Точный список зависит от исходного образа.

На стадии удаления возможностей общее число обнаруженных записей показано отдельно от выбранных для удаления и сохраняемых по правилам сборки. Итог отдельно считает успешные удаления, ошибки и операции, отложенные из-за незавершённого обслуживания. Ошибка удаления DISM записывается в журнал, после чего обработка продолжается со следующей выбранной возможностью.

### Что `balanced` явно сохраняет

- Microsoft Store, Store Purchase App и Desktop App Installer;
- существующий winget и службы лицензирования/развёртывания Store/MSIX;
- VCLibs, UI.Xaml, .NET Native и Windows App Runtime;
- WebView2 и Edge Update, нужные обычным приложениям;
- Hyper-V, WSL, контейнеры, сеть и обслуживание Windows Update;
- Notepad, базовый просмотрщик фото, Language.Basic и обязательные сетевые возможности;
- Windows Script Host/VBScript для скрытого запуска установки.

`-Keep` сохраняет указанную группу вопреки пресету:

```text
Defender, WinRE, Edge, Fonts, Speech, WMP, IE, Sandbox, AI,
Apps, Family, ToDo, OneDrive, NativeImages
```

Примеры: `-Keep Edge,Defender`, `-Keep Family,ToDo`, `-Keep Apps`. `Apps` также сохраняет Family и To Do. `Sandbox` оставлен как совместимый селектор; текущие таблицы не выбирают Windows Sandbox для удаления.

> [!CAUTION]
> `balanced` удаляет Microsoft Defender, защиту SmartScreen политикой и приложение «Безопасность Windows». Выберите `safe` или `-Keep Defender`, если встроенный антивирус должен остаться.

## OOBE, обновления и скрытый запуск

По умолчанию сборщик не позволяет установщику Windows скачивать обновления во время OOBE:

1. В проходе `specialize` создаётся временная блокировка исходящей сети, запоминаются включённые адаптеры и отключаются только они.
2. SetupComplete повторяет поиск адаптеров, появившихся позже.
3. При первом входе финализатор ждёт системный сигнал `OOBEComplete`.
4. Он возвращает только изменённые сборщиком адаптеры, удаляет своё правило и временные политики Windows Update/OOBE, затем завершает очистку Edge.

`-NoOobeNetworkBlock` оставляет сеть доступной во время OOBE.

Если сохранённый адаптер ещё не появился или его включение не подтверждено, состояние восстановления и задача сохраняются. Финализатор повторяет поиск, при смене GUID использует однозначное совпадение PnPDeviceID и восстанавливает остальные карты независимо от ошибки одной из них. Планировщик повторяет неуспешный запуск до трёх раз с интервалом в минуту, затем остаётся повтор при следующем входе. Чужие отключённые адаптеры сохраняют своё состояние.

Чтобы убрать короткое чёрное окно PowerShell, все пресеты сохраняют VBScript и создают текстовый `Run-Setup.vbs`, если в образе присутствуют `wscript.exe` и `vbscript.dll`. WScript создаёт первый PowerShell сразу скрытым, ждёт результат и возвращает его код. Собственный EXE не компилируется и не встраивается. Если в исходнике нет хоста или движка, сборщик сообщает о прямом запуске PowerShell, при котором начальная консоль может появиться.

VBS и PowerShell пишут в общий ежедневный `Logs\YYYY-MM-DD.log` с пометками `vbs-launcher` и `launcher`. Новый запускатель прошёл тесты с настоящим WScript на безопасной фикстуре; видимость окна и реакция антивируса при полной установке в VM ещё проверяются.

## Обновления, winget и подготовка без сети

Все выбранные загрузки готовятся до очистки рабочего каталога, копирования ISO и монтирования WIM:

- Windows LCU и обязательные checkpoint-пакеты;
- накопительное обновление .NET Framework;
- языковые пакеты Windows и LCU для исправления их ресурсов;
- языки WinPE/Setup и совместимый LCU загрузочного образа;
- bundle winget, лицензия и зависимости;
- DISM/oscdimg для новых веток образа.

После успешной подготовки остальная сборка не требует сети. Незавершённые `.part` не принимаются. Кэш проверяется по размеру и SHA-256 и сохраняется при отмене. При ошибке необязательной загрузки мастер называет компонент и предлагает пропустить его или отменить сборку; неинтерактивный запуск отменяется, а не меняет состав молча.

`-WithUpdates` включает поиск/загрузку. `-UpdateMode local` использует MSU из `-UpdatesDir`; `-LcuFile` и `-DotNetUpdateFile` выбирают цель при нескольких файлах. `-ResetBase` задаётся явно, потому что делает установленные обновления неудаляемыми.

Если App Installer/winget уже есть в редакции, мастер сохраняет его и не задаёт вопрос о загрузке. `-WithWinget` интегрирует новый пакет и не нужен для сохранения исходной версии.

## Языки Windows и установщика

Язык интерфейса Windows и язык Setup/WinPE выбираются отдельно.

| Команда | Результат |
| --- | --- |
| `-DownloadLanguage ru-RU` | Скачать и добавить русский; первый язык становится основным. |
| `-AddLanguage ru-RU -LanguageSource <путь>` | Добавить пакеты из локального Languages and Optional Features. |
| `-SetupLanguage auto` | Установщик следует за первым подготовленным языком Windows; по умолчанию. |
| `-SetupLanguage original` | Сохранить исходный язык установщика. |
| `-SetupLanguage de-DE` | Выбрать язык установщика независимо. |
| `-SetupLanguageSource <WinPE_OCs>` | Использовать локальные CAB WinPE. |
| `-LanguageUpdatePath <LCU.msu>` | Повторно применить совместимый LCU после добавления языков Windows. |
| `-SetupLanguageUpdatePath <LCU.msu>` | Исправить обновлённый `boot.wim` после добавления языка. |

Автоматическая подготовка языков WinPE сейчас поддерживает build 26100 amd64. Для других билдов нужен совместимый локальный источник, если требуемого языка уже нет в `boot.wim`. Для носителя 26100.1742 автоматически готовится исходный LCU KB5043080.

Состав пакетов читается из закреплённых установщиков Microsoft ADK; собственного сгенерированного каталога нет. Извлекаются только выбранные языки и шрифты.

## Учётные записи и answer-файл

Для любой поддерживаемой редакции `-AccountMode auto` предлагает:

1. создать/настроить пользователя при установке Windows — по умолчанию;
2. ввести локального пользователя сейчас и записать его в answer-файл.

В неинтерактивной сборке используйте `-AccountMode setup` либо задайте `-LocalUserName` и, при необходимости, SecureString `-LocalUserPassword`. Автоматический вход не включается. Пароль в answer-файле можно восстановить: кодирование Windows не является шифрованием.

`-Unattend <файл>` передаёт управление собственному answer-файлу. `-Unattend none` запрещает добавлять `autounattend.xml`. В этом случае пользователь отвечает за OOBE, аккаунт и первый вход.

Обходы TPM, Secure Boot, CPU, RAM и накопителя включены по умолчанию. `-NoBypass` убирает их. Сборщик также предотвращает автоматическое шифрование устройства и отключает резервное хранилище для новой установки.

### Файлы памяти установленной Windows

По умолчанию новые сборки используют **подкачку 128–1024 МБ**, отключают `swapfile.sys`, гибернацию/быстрый запуск и аварийные дампы памяти. Настройки независимы от пресета и сжатия ISO. Мастер показывает отдельные варианты, `-DryRun` — выбранные значения; они сохраняются в `MemoryFiles` паспорта сборки.

| Параметр | Значение по умолчанию и действие |
| --- | --- |
| `-PageFileMode custom|system` | `custom`: заданный диапазон; `system`: размер подкачки выбирает Windows. |
| `-PageFileMinMB <МБ>` | `128`: начальный размер `pagefile.sys`. |
| `-PageFileMaxMB <МБ>` | `1024`: верхняя граница роста. Для фиксированных 128 МБ задайте `-PageFileMaxMB 128`. |
| `-SwapFile disabled|system` | `disabled`: запрос отключения через `SwapfileControl=0`; `system`: удалить override и оставить управление Windows. |
| `-Hibernation disabled|system` | `disabled`: выключить гибернацию, быстрый запуск и `hiberfil.sys`; `system`: сохранить настройки исходного образа. |
| `-CrashDumps disabled|system` | `disabled`: выключить аварийные дампы (`MEMORY.DMP`/Minidump), полные live-дампы, журнал DumpStack и настройку отдельного файла дампа; `system`: сохранить исходные настройки. |

Маленькая подкачка ограничивает суммарную память, доступную приложениям. Для тяжёлых задач увеличьте `-PageFileMaxMB` или выберите `-PageFileMode system`. Без гибернации недоступен быстрый запуск, без дампов — соответствующие данные для разбора сбоев. Сжатие памяти в RAM эти параметры не отключают.

У `swapfile.sys` нет документированного штатного ограничения до 16 МБ: фактический размер в одной системе не гарантируется на другой. `SwapfileControl` — недокументированный override, его действие и совместимость приложений Store/MSIX требуют проверки на целевой Windows. Для штатного управления используйте `-SwapFile system`.

Параметры записываются во все ControlSet куста SYSTEM образа и повторяются при подготовке/завершении установки. Существующие разделы реестра, соседние значения и подразделы сохраняются; при ошибке выводится полный путь параметра. Подкачка/swap и DumpStack могут окончательно изменить размер или исчезнуть только после перезагрузки; сборщик сам её не запускает. После финализации `C:\Windows\Setup\Scripts\Win11Lite\memory-files-report.json` содержит запрошенные настройки и наблюдавшиеся размеры. Это снимок на момент финализации, а не обещание размера после перезагрузки. Guard не переустанавливает эти параметры при каждом входе.

Размер VMDK, размер ISO и занятое место на C: — разные измерения. Сравнивайте занятое место внутри обеих Windows с учётом файлов памяти. Одинаковый размер на разном оборудовании не гарантируется. См. документацию Microsoft о [подкачке](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows), [powercfg](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options) и [полных live-дампах](https://learn.microsoft.com/en-us/windows/win32/wer/wer-settings).

## Требования и поддерживаемые образы

- Windows с Windows PowerShell 5.1 или PowerShell 7;
- права администратора для реальной сборки, запрашиваются автоматически;
- оригинальный ISO Windows 11 x64;
- около 30 ГБ, с текущими обновлениями — около 45 ГБ;
- Windows ADK Deployment Tools либо сеть/кэш для подготовки совместимых инструментов;
- интернет только для выбранных элементов, которых нет в кэше.

До подготовки загрузок и рабочих файлов сборщик требует не менее **30 ГБ свободного места на рабочем диске, с обновлениями — 45 ГБ**. Если места недостаточно или его объём не удаётся определить, он запрашивает другой рабочий каталог и повторяет проверку до ввода подходящего пути. Без интерактивного ввода сборка завершается с ошибкой; нужно передать другой `-WorkDir`. `-DryRun` по-прежнему может показать план. Автоматический выбор диска действует только без явно выбранного рабочего пути и выбирает диск, полностью соответствующий требованию.

Распознаваемые ветки Windows 11:

| Build | Выпуск |
| ---: | --- |
| 22000 | 21H2 |
| 22621 | 22H2 |
| 22631 | 23H2 |
| 26100 | 24H2 |
| 26200 | 25H2 |
| 28000 | 26H1 |

Неизвестная ветка останавливается и не получает обновления/инструменты другой версии. Для build 28000 сборщик умеет подготовить закреплённые x64 DISM 10.0.28000.1 и oscdimg из пакетов Microsoft ADK, не заменяя установленный ADK. См. [разбор совместимости 26H1 Home/Pro и Store/MSIX](COMPATIBILITY.md).

## Ярлык установки Firefox

Сборщик сообщает язык загрузки Firefox при формировании ярлыка, после завершения интеграции языков Windows.

Готовая Windows получает `Install-Firefox.cmd` на общем рабочем столе. При запуске он:

1. пробует только источник `winget`, не завися от сломанного `msstore`;
2. выбирает пакет языка Windows: `Mozilla.Firefox.ru` для ru-RU, базовый `Mozilla.Firefox` для en-US и локализованные ID для остальных известных языков;
3. при отказе скачивает `firefox-latest` с Mozilla на том же языке;
4. удаляет одноразовый ярлык только после успеха.

При ошибке скачивания или отмене установки ярлык остаётся для повторного запуска.

## Результаты, журналы и аудит

| Файл | Назначение |
| --- | --- |
| `*_lite.iso` | Загрузочный результат. |
| `*_lite.sha256` | Контрольная сумма SHA-256. |
| `*_lite.image-audit.json` | Размер хранилища компонентов, отказы удаления и цели, оставшиеся по данным DISM. |
| `*_lite_winre.wim` | Необязательная сохранённая копия WinRE. |
| `win11-lite-build.json` в корне ISO | ID сборки, источник/результат, пресет, Keep, язык, обновления и Guard. |

Журналирование сборщика создаёт основной `.log`, `.details.log` для команд/диагностики и `.dism.log`. DISM может показать несколько внутренних проходов 0–100%; `100% — готово` выводится только после успешного завершения процесса.

Любая полоса прогресса сборщика после пяти минут без изменения видимого целого процента переключается на бегущий индикатор `...`, а таймер продолжает считать время. Скрытые изменения `1,1% → 1,9%`, отображаемые как `1%`, не сбрасывают этот отсчёт. Новая цифра на экране автоматически возвращает полосу с процентом; переключение может повторяться в одной операции. Правило действует для операций DISM, копирования файлов и создания ISO. При сообщении 100% от ещё работающего процесса сохраняется прежний индикатор ожидания завершения.

Гостевые файлы находятся в `C:\Windows\Setup\Scripts\Win11Lite`. Для разбора VM нужны ежедневные файлы за нужные даты из `Logs` и последние `guard-report.txt/json`. Записи помечены как `prepare`, `finalize`, `launcher`, `vbs-launcher` или содержат ID проверки Guard. Журналы сборщика на хосте не показывают действия после загрузки Windows.

## Состояние проверок

На 17.09.2026 четырнадцать наборов содержат **1 304 проверки**. Те 1 292, что были до исправления окна отчёта Guard, прошли на каждой из Windows PowerShell 5.1 и PowerShell 7; 12 добавленных для этого исправления пока выполнялись только на Windows PowerShell 5.1, потому что PowerShell 7 на использованной машине не установлен. Там прошли все 14 наборов. Они проверяют парсеры, безопасные пути, место на рабочем диске, загрузки/кэш, WIM/ADK, языки, answer-файлы, правила удаления, отчёты/историю Guard, ротацию журналов, сеть OOBE, файлы памяти, дочерние процессы, прогресс, CMD и VBS. Для изменения файлов памяти и сети прошли восемь затронутых наборов: **646 проверок на каждой версии PowerShell**; остальные наборы не перезапускались. DryRun на реальном ISO проверен на RU/7 и EN/5.1. Правка чтения ISO прошла все 151 проверки Servicing на каждой версии, включая реальную файловую блокировку при подмене API подключения ISO. Последнее исправление реестра прошло MemoryFiles 72 и SingleFile 45 на каждой версии (117 проверок), включая настоящие операции реестра и ACL с запретом удаления в одноразовой фикстуре HKCU. Изменение счётчиков возможностей прошло все 246 проверок Main на каждой версии, включая продолжение после ошибки удаления с подменённым DISM.

Тесты Guard, OOBE, реестра, служб и обслуживания используют контролируемые фикстуры для системных операций. Проверки сохранности реестра также используют настоящий провайдер в одноразовом разделе HKCU, куда перенаправляются пути HKLM. Они не выдаются за результат VM. Реальные сборки и прошлые журналы VM подтверждают значительную часть 24H2/26H1; текущие изменения файлов памяти/сети, новый VBS-запускатель, локализованная установка Firefox через winget и исключение VBScript в `max` требуют свежей установки.

```powershell
$suites = 'Test-SingleFile', 'Test-Win11Lite', 'Test-WindowsBatch', 'Test-WingetDetection', 'Test-Guard', 'Test-GuardModes', 'Test-GuestLogs', 'Test-Downloads', 'Test-SetupLanguage', 'Test-OobeNetwork', 'Test-SetupLauncher', 'Test-Compatibility', 'Test-Servicing', 'Test-MemoryFiles'
foreach ($suite in $suites) {
    powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File ".\tests\$suite.ps1"
    if ($LASTEXITCODE -ne 0) { throw "Не прошёл $suite" }
}
```

Для PowerShell 7 замените `powershell.exe` на `pwsh.exe`. Наборы Guard запускайте последовательно.
