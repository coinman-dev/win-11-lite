# Изменения

## 2026-09-14

### Бегущий индикатор после пяти минут без прогресса

- Все полосы сборщика (DISM, копирование, создание ISO) после пяти минут без изменения процента показывают бегущий индикатор `...` с таймером. Новый процент автоматически восстанавливает обычную полосу; последующие паузы снова переключают её на анимацию.
- Повтор одинакового процента и обычный текст процесса не сбрасывают таймер отсутствия прогресса. Учитывается дробное продвижение; новый внутренний этап тоже начинает отсчёт заново. После 100% от работающего процесса сохраняется прежнее ожидание, а успех или ошибка показываются по коду завершения.
- Main прошёл на PowerShell 5.1 и 7: по 241 проверке, включая реальные дочерние процессы с ускоренными часами для stdout, stderr и внешнего счётчика. Проверены граница пяти минут, повторные паузы/возобновления, RU/EN, узкая консоль и завершение с ошибкой. Реальная сборка с новой индикацией не запускалась.

### Однозначный вопрос о продолжении без загрузки

- В вопросе после необязательной ошибки загрузки теперь прямо написано: «Введите Да чтобы продолжить сборку». Логика не менялась: `да` продолжает без компонента, `нет` или Enter отменяют сборку до обработки образа.

### Итоговый язык Firefox при создании ярлыка

- Сообщение «Язык для загрузки Firefox» перенесено к формированию `Install-Firefox.cmd`, после интеграции языков. Оно выводится один раз с итоговым языком и при добавлении языковых пакетов, и при сохранении языка исходного ISO; ранний вывод `en-US` при выбранной русификации убран.

### Обязательный выбор другого рабочего каталога при нехватке места

- Недостаток места больше не остаётся предупреждением: до подготовки загрузок и рабочих файлов сборщик требует 30 ГБ, с обновлениями — 45 ГБ. Диалог повторно запрашивает путь, пока не найден безопасный каталог на диске с достаточным местом; пустой ответ не продолжает сборку.
- Без интерактивного ввода нехватка или невозможность измерить место останавливает сборку с подсказкой `-WorkDir`. `DryRun` сохраняет возможность показать план. Автоматический перенос без явно заданного пути выбирает только диск, соответствующий полному требованию.
- Рабочие пути и кэш по умолчанию рассчитываются после выбора подходящего каталога; явно заданный кэш сохраняется. Сравнение места использует точное значение, недостаток не округляется в сообщении до требуемого минимума. Подсказка мастера теперь указывает оба порога: 30/45 ГБ.
- На PowerShell 5.1 и 7 прошли Main 182, Downloads 80 и SingleFile 45: по 307 проверок. Новый диалог проверен с подменой ввода и свободного места, включая 43,3/45 ГБ, повторные ошибки, границы порога, безопасные пути и расчёт кэша/монтирования; реальная сборка ISO не запускалась.

### VBScript сохраняется и в max

- По явному выбору пользователя VBScript стал исключением из агрессивного удаления `max`: он нужен для скрытого запуска установки. Удаление WMIC сохраняется.
- Пакеты VBScript (включая языковые) и его capability защищены от `RemoveExtra`; та же защита передаётся guard. Выбор VBS больше не зависит от пресета, только от наличия хоста и движка в образе.
- Compatibility 133, Guard 109 и SetupLauncher 80 прошли на PowerShell 5.1 и 7: по 322 проверки с подменой системных действий. Новый max в VM ещё не проверен.

### Запуск PowerShell через текстовый VBS при установке

- В safe/balanced при наличии Windows Script Host и VBScript три точки Windows Setup запускаются через встроенный текстовый `Run-Setup.vbs`: specialize/prepare, SetupComplete/prepare-register и первый вход/finalize. `wscript.exe` создаёт PowerShell с изначально скрытым окном, ждёт завершения и возвращает его код.
- VBS допускает только фиксированные фоновые режимы, запускает только соседний `Win11Lite.ps1` и пишет ошибки/коды в `vbs-launcher.log`. Рабочий процесс и его `launcher.log` сохранены. Собственный EXE не создаётся; для сборки по-прежнему нужен только один PS1.
- В первой версии max сохранял удаление VBScript и использовал PowerShell; затем пользователь выбрал сохранение VBScript и в max (см. выше). При отсутствии хоста/движка VBS в образе остаётся PowerShell с сообщением сборщика. Окна отчётов guard Standard/Debug/Silent не изменены.
- Проверка зависимостей VBS повторяется после последнего обслуживания DISM, чтобы не выпустить ISO с пропавшим запускателем. Проверка отображения при реальной установке в VM ещё требуется.
- На PowerShell 5.1 и 7 прошли по 598 связанных проверок: SetupLauncher 80, SingleFile 45, Servicing 135, Win11Lite 154, Guard 107, GuardModes 39, OOBE 38. Настоящий WScript запускает безопасную копию гостевого сценария; проверены скрытое начальное окно, отсутствие консоли у worker, ожидание, коды возврата, отсутствующий файл и недопустимые аргументы. Системные действия гостевого сценария подменены.

### Язык Firefox при установке через winget

- Для русского образа ярлык устанавливает пакет `Mozilla.Firefox.ru`; основной `Mozilla.Firefox` в текущем каталоге содержит только en-US и давал английский интерфейс на русской Windows.
- Для en-US сохраняется `Mozilla.Firefox`, для других языков используется идентификатор `Mozilla.Firefox.<код Mozilla>`. Источник `winget` задан явно; при отсутствии локализованного пакета остаётся прямая загрузка нужного языка с Mozilla.
- Все 20 языковых кодов сборщика сверены с актуальными каталогами winget; WindowsBatch прошёл на PowerShell 5.1 и 7: по 151 проверке, включая русский, английский, немецкий и резервную загрузку.
- Реальная read-only проверка `Ru_Windows_11_26H1_28000.2704.ISO` определила ru-RU для Home и Pro; для обоих индексов сформированы `Mozilla.Firefox.ru` и резервный URL `lang=ru`.

### Один параметр Guard

- `-Guard` теперь принимает значение: `None`, `Standard`, `Debug` или `Silent`. `-Guard None` и значение по умолчанию не встраивают guard; остальные значения одновременно включают его и задают вид отчёта.
- Отдельные параметры `-GuardMode` и `-GuardDebug` удалены. Мастер показывает один список из четырёх режимов, выбирает Standard по умолчанию и формирует команду вида `-Guard Standard`.
- В паспорте сборки поле `Guard` содержит выбранный режим. Дублирующие поля `GuardMode` и `GuardDebug` удалены; гостевой сценарий проверяет допустимое значение до регистрации задач.
- Все 12 наборов прошли на PowerShell 5.1 и 7: по 1020 проверок. Реальный DryRun Pro 26H1 прошёл для `None`, `Standard`, `Debug` и `Silent`; старые `-GuardMode` и `-Guard` без значения отклоняются при разборе команды.

## 2026-09-13

### Точечное сохранение Family и To Do

- `-Keep Family,ToDo` сохраняет эти два приложения из исходного ISO, не отменяя остальные удаления пресета. Можно сохранить только одно из них. Guard получает тот же выбор и не удаляет сохранённые приложения.
- Family и ToDo стали отдельными группами; общий `-Keep Apps` по-прежнему сохраняет оба приложения. Мастер включает `Keep` в показываемую команду повторного запуска, выбор записывается в паспорт сборки.
- Проверки: Compatibility 128 и Guard 105 на каждой из PowerShell 5.1/7; реальный DryRun Pro 26H1 с `-Keep Family,ToDo` и отдельным выходным ISO прошёл. Полная сравнительная сборка не запускалась.

### Family/To Do и команды управления guard

- `balanced` и `max` удаляют Family (`MicrosoftCorporationII.MicrosoftFamily`) и Microsoft To Do (`Microsoft.Todos`). Правило входит в группу Apps, передаётся guard и учитывает `-Keep Apps`.
- Каталог ожидаемых приложений guard дополнен Family/To Do и недавно добавленными медиаплеерами/Xbox: их отсутствие и отказ инвентаризации теперь также отражаются по именам.
- В краткий и подробный отчёты добавлены команды `schtasks.exe /Change /TN "\win-11-lite guard" /Disable` и `/Enable` с указанием запуска от администратора. Они доступны в Standard/Debug и сохранённых отчётах. Отключение запрещает будущие запуски; текущая проверка завершается. После включения guard запускается при следующем входе. Своего средства управления или новой задачи не требуется.
- Проверки на PowerShell 5.1 и 7: по 291 (Compatibility 110, GuardModes 39, Guard 100, SingleFile 42). Системные API подменены; команды изменения задач на хосте не выполнялись. Удаление Family/To Do и новый вывод в VM ещё не проверены.

### Один гостевой сценарий вместо пяти; папок data и tools больше нет

- Run-Setup.ps1, Prepare.ps1, Finalize.ps1, guard.ps1 и Guard.UI.ps1 объединены в один `Win11Lite.ps1`, который сборщик пишет в образ. Режимы: prepare, prepare-register, finalize, finalize-wait, guard и view. Все точки входа — SetupComplete, answer-файл и три задачи планировщика — запускают этот файл, отличая только режим.
- Подстановка текста при сборке убрана. Вместо шести плейсхолдеров гостевой сценарий читает build-info.json, куда добавлены ManageOobe и RemoveEdge. Отсутствующее значение останавливает работу, а не подставляет тихое умолчание. Язык теперь только в build-info.json; из guard.json он удалён.
- Три разных записи журналов и три копии P/Invoke OOBEComplete заменены одной. Имена журналов и отчётов не изменились: launcher.log, prepare.log, finalize.log, guard.log, guard-summary.txt, guard-report.txt/json, guard-state.json, guard-run.json.

- Проверено: 847 проверок на runtime на PS 5.1 и 7. Меньше, чем 854 до объединения, потому что проверки для исчезнувших отдельных файлов и режима guard-debug удалены, а вместо них добавлены проверки единого файла: настоящий Start-GuestChild на пропатченной копии, реальная очистка Edge внутри guard и её отказ, заглушки сети, падающие при попытке восстановить связь.

### Состав ADK читается из установщиков Microsoft

- Встроенные каталоги deployment-tools-28000.json и winpe-26100.json удалены. Состав архивов скрипт читает при сборке из MSI ADK: таблицы File, Component, Directory и Media дают настоящие имена и размеры файлов, спрятанных в CAB под именами fil<хеш>. Установщики только читаются, установка не запускается.
- В скрипте закреплены лишь адреса, размеры и контрольные суммы: 4 установщика инструментов 26H1 (2 445 312 байт) с 9 архивами (6 641 932 байта) и 1 установщик WinPE (1 015 808 байт) с 2 языковыми архивами. Расхождение SHA256 останавливает сборку с подсказкой про -SetupLanguageSource и -DismPath.
- Главный файл уменьшился с 605 093 до 389 904 байт и с 12 013 до 5 581 строки. Целостность сохранена: содержимое подтверждается закреплёнными SHA256 архивов и размерами из таблиц MSI; подписи MSI, dism.exe и oscdimg.exe проверяются как предупреждение, чтобы отсутствие корневого сертификата не ломало верную сборку.
- Ключ подготовленного кэша инструментов теперь SHA256 закреплённых источников, поэтому имеющийся комплект 28000 один раз скачивается заново. Кэш языков WinPE проверяется по файлам и остаётся годным.
- Проверено на PS 5.1 и 7: оба прочитанных состава совпали с удалёнными каталогами полностью (194 и 894 файла), подготовленный DISM 10.0.28000.1 подписан Microsoft и запускается, oscdimg 2.56 запускается, готовый кэш не перечитывает установщики. Наборы тестов — 854 проверки на runtime; ранее не покрытая ветка загрузки WinPE теперь проверяется.

- Для сборки достаточно скачать win-11-lite.ps1: три служебных PS1 и два каталога JSON встроены обычным текстом. Соседние data/tools не используются сборщиком; необходимые сценарии записываются в образ автоматически.

- Сохранён прежний хеш каталога DISM для повторного использования подготовленного кэша. Загрузки компонентов и инструментов остаются перед обработкой образа.
- Добавлены 23 проверки отдельной копии файла на PS 5.1/7, включая LF-формат скачивания с GitHub, точность ресурсов и запись PS1 с UTF-8 BOM. Реальные DryRun Home/Pro ISO 28000.2704 прошли из папки с одним PS1. Полная сборка после этого изменения не выполнялась.

### Режимы guard и одно окно отчёта

- Добавлен отдельный `-GuardMode Standard/Debug/Silent` и старый совместимый GuardDebug. Позже эта пара заменена единым `-Guard None/Standard/Debug/Silent`, см. текущие изменения выше.
- Прежний наблюдатель с триггером входа и цепочкой PowerShell-процессов заменён задачей `win-11-lite guard report` без триггера. SYSTEM-worker запускает один просмотрщик прямо в пользовательской сессии после проверки OOBE; собственный EXE не добавлялся.
- Краткий итог считает уникальные программы, повторное появление независимо от успеха удаления и успешные повторные исправления. Неизвестные состояния и незавершённое удаление не считаются успехом. Полные пути остаются в подробных файлах; в Standard показаны только счётчики и короткие ошибки.
- Update-InstalledGuard принимает GuardMode, переносит существующие задачи и Prepare-регистрацию, сохраняет настройки и резервные копии, экспортирует runtime-update.json для проверки установленной версии. Старый пакет без Mode впервые переводится в Standard.
- Гостевые журналы 26H1 подтвердили успешное применение прежнего обновления guard и отсутствие ошибок записи, но обнаружили пять RemoveFileSystemItemArgumentError (0x80070057) после успешных takeown/icacls. Для этого отказа добавлена ограниченная повторная попытка удаления указанного файла без изменения атрибутов; переходы через ссылки каталогов и выход за выбранный путь запрещены. Исправление в VM ещё не подтверждено.

### Подтверждение пароля локальной учётной записи

- В интерактивном мастере непустой пароль предварительно создаваемой локальной учётной записи теперь запрашивается с подтверждением. При несовпадении пароль и подтверждение вводятся заново; пустой пароль по-прежнему не требует повторного ввода.
- `-LocalUserPassword` остаётся параметром SecureString без лишнего интерактивного запроса. Сравнение подтверждения не создаёт управляемую строку с открытым паролем.

### Guard после обновления Windows: диагностика файловой очистки

- В журнале старого ISO после большого обновления: 58 проверок, удалён Language.OCR для ru-RU, 10 отказов доступа к вернувшимся каталогам. Политики и службы прошли проверки; точный этап отказа старый guard не записывал.
- При ошибке теперь сохраняются этап, тип и код исключения, проблемный объект; стек — в guard.log. Коды takeown/icacls и последние 12 строк вывода при отказе больше не теряются. Попытка удаления сохраняется, если подготовка прав не удалась, но имеющегося доступа достаточно.
- Отказ проверки пути после удаления больше не может дать ложный успешный результат.
- Guard: 69 проверок на PS 5.1/7, включая подменённые отказы на разных этапах и реальный stderr безопасного дочернего процесса. Причина отказов доступа в VM ещё не подтверждена; изменение не заявлено как их исправление. Общий состав — 722 проверки на версию.

### PowerShell-запуск и подробные итоги guard

- Собственный Win11Lite.Run.exe, исходник C# и стадия компиляции удалены после сообщения о реакции антивируса. Все точки входа используют штатный PowerShell и Run-Setup.ps1 с сохранением кодов возврата и launcher.log; ожидание OOBE для наблюдателя сохранено.
- Guard вынесен в data/guard.ps1. Итоговый отчёт перечисляет имена, найденное и отсутствующее, успешные удаления, уже отключённые службы, новые и повторные изменения, ожидание завершения, ошибки и непроверенные пункты. Повторность подтверждается историей успешных наблюдений.
- Последний полный итог показывается в окне наблюдателя и сохраняется в guard-report.txt/json; история — в guard-state.json. Отказ получения списка не превращается в ложное «не найдено».
- Добавлен Update-InstalledGuard.ps1 для готовой VM: резервные копии, перевод существующих задач на PowerShell, сохранение их состояния и удаление старого EXE. Он не запускает проверку guard немедленно.
- На PS 5.1/7 прошли 61 проверка guard и 57 проверок запуска/обновления; общий состав — 714 на версию. Начальное окно штатного PowerShell на ранних этапах Setup может кратко появиться; полная VM-проверка новой версии ещё требуется.
- Прочитаны 350 событий из Application/System/Setup: .NET KB5126052 установлен успешно после OOBE; окончание KB5124008 пока не зафиксировано. Ошибки активации и предупреждения функций безопасности VM требуют отдельной оценки, а не подавления журнала.

Ошибка записи неверно попадала в счётчик ошибок компонентов и прерывала обход на 31 из 57 проверок. Это соответствует [ошибке PowerShell #5924](https://github.com/PowerShell/PowerShell/issues/5924).

- На PowerShell 5.1/7 прошли 49 проверок guard, включая реальные совместные и исключительные файловые блокировки. Остальные наборы не изменены; общий состав — 699 на версию.

### Промежуточные 100% DISM

- Вместо 100% у ещё работающей утилиты показываются движущаяся полоса, «ожидание завершения» и прошедшее время. После нового внутреннего этапа обычный процент возвращается.
- `100% — готово` появляется только после успешного выхода процесса; ошибка после промежуточных 100% показывается как ERR.
- Таймер продолжает обновляться, даже если stdout/stderr уже закрылись, а процесс ещё не вышел.
- Проверены реальные дочерние процессы с паузой после 100%, успешным и ошибочным выходом; раннее закрытие потоков, анимация, RU/EN и узкие консоли.

### Логирование без подробных команд в консоли

- `-Debug`, `-LogFile` и включение журнала в мастере больше не включают общий verbose/debug-вывод PowerShell.
- Команды DISM, технические сообщения процессов, вывод oscdimg и подробности ошибок шрифтов записываются в `.details.log`. Основной transcript и собственный `.dism.log` используют отдельные файлы.
- Явный `-LogFile` также включает журнал DISM уровня 4. `-Debug:$false` не включает логирование; относительный путь журнала разрешается относительно текущей папки PowerShell.
- Проверены запись команд без загрязнения результата DISM, сохранение ошибок, кириллица в PowerShell 5.1/7 и отсутствие «ПОДРОБНО» в DryRun с `-Debug -Verbose`.

### Повторные обновления OOBE и одноразовый ярлык Firefox

- Подготовка повторяет обнаружение адаптеров, а SetupComplete заново проверяет блокировку сети. Временное правило брандмауэра действует и для поздно появившихся интерфейсов.
- Финализатор проверяет системный сигнал OOBEComplete, включая запуск через FirstLogonCommands. До завершения OOBE сеть не восстанавливается; ожидание выполняется скрыто, не удерживая запуск рабочего стола.
- Возврат адаптеров, снятие сетевого правила и восстановление временных политик выполняются независимо. Поздний Prepare не блокирует сеть повторно после завершения OOBE.
- Install-Firefox.cmd удаляет себя после успешной установки через winget или прямой установщик. При ошибке или отмене файл сохраняется. Право удалить только этот одноразовый файл доступно обычным пользователям.
- Успех winget проверяется по точному коду 0: отрицательные HRESULT больше не принимаются за успешную установку.
- Добавлены проверки позднего появления адаптера, раннего первого входа, восстановления сети при сбоях и настоящего самоудаления CMD. Итог: 479 проверок на каждой версии PowerShell; проверка нового поведения в VM ожидается.

### Подготовка загрузок до сборки

- Обновления Windows и .NET, языковые пакеты, winget с лицензией и зависимостями, а также пакеты установщика готовятся до копирования ISO и обслуживания WIM.
